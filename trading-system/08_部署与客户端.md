# 部署架构与客户端方案

> 目标：把这套三桶策略系统从「本地手工跑脚本 + 看 CSV」升级为「云端定时执行 + 消息推送 + 手机/桌面端记账查收益」的一体化产品。
> 定位不变：**Agent 只出提醒，买卖仍由人拍板**；客户端仅做记账、看板、提醒展示，不接券商 API、不自动下单。

---

**三个物理组件**：GitHub 仓库（存代码/配置/日志）+ GitHub Actions（跑计算）+ 客户端（记账看板）。

**一个逻辑原则**：`07_信号台账.csv` 与 `04_交易日志.csv` 是唯一事实源。所有客户端展示、所有推送内容、所有回测比对，都从这两个文件派生。

### 2.2 GitHub Actions 工作流示例

一个日频扫描的最小 workflow：

```yaml
# .github/workflows/daily.yml
name: T1 每日盘后风控

on:
  schedule:
    # UTC 08:00 = 北京时间 16:00，仅交易日跑；节假日过滤在脚本内做
    - cron: "0 8 * * 1-5"
  workflow_dispatch:   # 允许手动触发

jobs:
  run:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.REPO_WRITE_PAT }}   # 需要写回 data/ 的 PAT

      - name: 交易日判断
        id: trading_day
        run: python scripts/lib/is_trading_day.py
      - if: steps.trading_day.outputs.is_trading_day != 'true'
        run: echo "非交易日，跳过" && exit 0

      - uses: actions/setup-python@v5
        with: { python-version: "3.11", cache: "pip" }
      - run: pip install -r scripts/requirements.txt

      - name: 拉行情 + 跑 T1
        env:
          TUSHARE_TOKEN: ${{ secrets.TUSHARE_TOKEN }}
          WESTOCK_TOKEN: ${{ secrets.WESTOCK_TOKEN }}
        run: python scripts/t1_daily_risk.py

      - name: 推送提醒
        if: success()
        env:
          WECOM_KEY:   ${{ secrets.WECOM_BOT_KEY }}
          LARK_URL:    ${{ secrets.LARK_WEBHOOK }}
          SMTP_USER:   ${{ secrets.SMTP_USER }}
          SMTP_PASS:   ${{ secrets.SMTP_PASS }}
        run: python scripts/lib/notifier.py --report data/report_$(date +%F).md

      - name: 提交回写文件
        run: |
          git config user.name  "trading-bot"
          git config user.email "bot@users.noreply.github.com"
          git add data/live_signal_log.csv data/report_*.md
          git commit -m "T1 daily run $(date +%F)" || echo "no changes"
          git push
```

### 2.3 定时任务对照表

| 任务 | Cron (UTC) | 北京时间 | 触发脚本 | 推送等级 |
|---|---|---|---|---|
| T1 每日风控 | `0 8 * * 1-5` | 16:00 交易日 | t1_daily_risk.py | 有 P0 才推，否则日报存档 |
| T2 周度红利判定 | `30 0 * * 1` | 08:30 周一 | t2_weekly_dividend.py | 状态跃迁必推，否则日报 |
| T3 月度再平衡 | `30 1 1 * *` | 09:30 每月 1 号 | t3_monthly_rebalance.py | 偏离 >5pct 必推 |
| T6 候选池 | `0 12 * * 5` | 20:00 周五 | t6_candidate_pool.py + skill | 生成周末阅读材料，静默存档 |
| T7-C 月度回测 | `0 13 28 * *` | 21:00 每月 28 | t7_backtest.py --bucket C | 报告静默存档 |
| T7-AB 季末回测 | `0 13 28 3,6,9,12 *` | 21:00 季末 | t7_backtest.py --bucket AB | 报告静默存档 |
| T8 台账维护 | `0 9 * * 1-5` | 17:00 交易日 | t8_signal_log.py | 命中"实盘胜率<预期-10pct"必推 |
| T4 财报季扫描 | `0 11 * * 1` in 4/8/10 月 | 19:00 周一 | t4_earnings_scan.py + skill | 候选表静默存档 |
| T5 季度归因 | `0 12 28 3,6,9,12 *` | 20:00 季末 | t5_review.py + skill | 复盘报告静默存档 |

**推送等级约定**：
- **必推**：P0（止损/证伪/顶部反指/失效预警）、P1（买入/卖出/状态跃迁）。
- **静默存档**：报告写入 data/ 并 commit，不发通知；客户端可查阅。
- **数据缺失**：脚本抛异常 → Actions 自动失败 → GitHub 会发失败邮件，无需额外通道。

### 2.4 Secrets 与凭据管理

在 GitHub 仓库 Settings → Secrets and variables → Actions 里配置：

| Secret 名 | 用途 | 备注 |
|---|---|---|
| `TUSHARE_TOKEN` | tushare 行情 | 免费额度够用；付费更稳定 |
| `WESTOCK_TOKEN` | westock 官方源 | 如未来切回官方源 |
| `LLM_API_KEY` | Claude / DeepSeek 调用 | T4-C / T5 / T6 语义步骤 |
| `WECOM_BOT_KEY` | 企业微信群机器人 | webhook URL 的 key 部分 |
| `LARK_WEBHOOK` | 飞书自建应用 webhook | 完整 URL |
| `SMTP_USER` / `SMTP_PASS` | 邮箱 SMTP | 建议用 QQ/163 授权码，非登录密码 |
| `REPO_WRITE_PAT` | 回写 data/ 的 Personal Access Token | 权限只给 contents:write |
| `CLIENT_API_TOKEN` | 客户端后端拉取台账用 | 只读，随时可 rotate |

**注意**：`data/live_trade_log.csv` 涉及个人持仓，即使私有仓库也建议加密。可选方案：
- 简易：全靠仓库私有 + 2FA；
- 加固：文件用 `age` 或 `sops` 加密提交，运行时用 secret 密钥解密。

## 三、推送通知实现

### 3.1 三通道对照

| 通道 | 优点 | 缺点 | 推荐场景 |
|---|---|---|---|
| **企业微信群机器人** | 免费、无频率限制、支持 Markdown 卡片 | 需要一个企微组织（个人可申请） | P0/P1 首选 |
| **Server 酱 · 微信服务号** | 直接推到个人微信 | 免费额度每天 5 条；付费无限 | 只推 P0 |
| **飞书机器人 (webhook)** | 免费、支持富文本 + 交互按钮 | 需要飞书账号 | 备份通道，或团队协作 |
| **邮箱 (SMTP)** | 100% 到达、归档方便 | 时效性差 | 日报 / 周报 / 归因报告 |

### 3.2 消息模板（沿用 yaml `alerts.message_template`）

企微 Markdown 示例：

```markdown
### 🔴 P0 · 规则 C-E2 触发
**标的**：601088 中国神华（煤炭）
**当前值**：距高点回撤 -18.3%
**阈值**：drawdown_from_high_pct > 15
**建议动作**：清仓
**依据数据源**：akshare · 2026-07-31 15:00
**yaml 版本**：v1.2.0
**回测胜率**：72% (n=45, 90d)

[查看台账详情] [标记为已执行] [忽略本次]
```

后两个按钮跳转到客户端 App 深链，形成"提醒 → 决策 → 记账"闭环。

### 3.3 通知发送策略

- **P0**：三通道齐发（微信 + 飞书 + 邮件），5 分钟内未在客户端确认则重推 1 次。
- **P1**：企微 + 邮件，不重推。
- **P2/P3**：只写日报，日报按周汇总一次邮件。
- **失败降级**：任一通道失败自动切下一个，全部失败写 GitHub Issue（Actions 自带能力）。
- **静默时段**：22:00–08:00 只有 P0 会实时推，其它压到次日 08:30。

## 四、客户端（手机 / 桌面）

### 4.1 定位与边界

**做什么**：
- 记账：录入/编辑总资产、四桶权重、每笔买卖。
- 看板：实时展示组合净值、四桶权重、单票持仓、当日 P&L、历史回撤。
- 提醒中心：接收 GitHub Actions 推来的信号，一键标记「已执行 / 已忽略」。
- 台账查阅：只读浏览 `07_信号台账.csv`、`04_交易日志.csv`、每日报告。
- 手动确认：点击提醒后，跳到"执行确认页"填成交价/成交量，回写日志。

**不做什么**：
- 不接券商 API、不下单。
- 不做实时行情推送（那是券商 App 的事）。
- 不做深度回测（回测在 Actions 里跑，客户端只看结果）。

### 4.2 技术栈两个可选路线

**路线 A（推荐，个人低成本）：PWA + 云函数**
- 前端：Vue 3 或 SvelteKit + Tailwind，打包成 PWA，手机加桌面/桌面浏览器都能用。
- 后端：Cloudflare Workers 或 Vercel Functions（免费额度充裕）。
- 数据库：Cloudflare D1 (SQLite) 或 Turso 或 Supabase Free。
- 存储层同时读 GitHub 仓库里的 CSV（用 GitHub Contents API，只读），本地录入的持仓和交易另存 D1。
- 优点：零运维、可跨设备、发布只需 git push；缺点：无原生功能（生物识别、后台推送有限制）。

**路线 B（原生体验）：Flutter 或 Tauri**
- Flutter 一套代码出 iOS/Android/Windows/macOS 桌面。
- 或桌面为主：Tauri（Rust + Web 前端），体积小、性能好。
- 后端仍走 Cloudflare/Vercel。
- 优点：可用系统级推送、离线体验好；缺点：iOS 需要开发者账号（¥688/年）+ 发版流程。

**首版建议走路线 A**：3 天能做出可用版本，等你确认高频使用后再往路线 B 迁移；数据层同款，切换成本可控。

### 4.3 核心页面清单

| 页面 | 功能 | 数据来源 |
|---|---|---|
| **仪表盘** | 总资产、四桶权重环形图、当日 P&L、状态灯 (S0/S1/S2/S3) | 后端聚合 |
| **持仓** | 按桶分组列表，每行含代码/名称/持仓/成本/现价/浮盈；点进详情 | data/positions.csv |
| **交易录入** | 表单：日期/方向/桶/代码/价格/股数/触发规则ID/一句话理由 | 写 04_交易日志.csv |
| **提醒中心** | 收件箱式列表，未读优先；卡片显示信号详情 + 三键操作 | 07_信号台账.csv |
| **信号台账** | 表格 + 筛选（按桶/按规则/按胜率），可导出 | 07_信号台账.csv |
| **回测结果** | 各阈值网格结果表 + 敏感性图 | 06_*_result.csv |
| **归因报告** | 季度归因 Markdown 渲染 | data/report_*.md |
| **设置** | 通道 webhook 配置、静默时段、桶模式(保守/平衡/激进)切换 | 本地存储 |

### 4.4 关键交互：从"收到提醒"到"记账"的完整闭环

```
[GitHub Actions T1] 检测到 601088 触发 C-E2
        │
        ▼
[Notifier] 企微推送 Markdown 卡片，含 signal_id=20260731-C-E2-601088
        │
        ▼
[用户点击" 已执行 "] → 深链跳转到 App
        │
        ▼
[App 执行确认页] 预填规则/桶/标的，用户补：
      - 实际成交价 45.20
      - 实际成交股数 200
      - 情绪自评 3
        │
        ▼
[App 写入 04_交易日志.csv 一行] + [07_信号台账 该行 executed=Y, exec_price=45.20]
        │
        ▼
[App 触发 Actions webhook] 让 GitHub 同步一次
        │
        ▼
[T8 下次跑] 60/120/250 交易日后自动回补收益，与回测胜率对比
```

### 4.5 数据同步策略

- **权威源**：GitHub 仓库的 CSV。
- **客户端本地**：D1/Turso 缓存 + 一份 Redis-ish KV 存"最新一份聚合结果"。
- **写路径**：客户端写 → 后端 API 收到 → 后端调 GitHub Contents API 覆盖对应 CSV 行 → commit "trade log update via client"。
- **读路径**：客户端拉后端聚合结果（每 30s 轮询或 WebPush 事件驱动刷新）；后端定时（每 5 分钟）从 GitHub 拉最新 CSV。
- **冲突解决**：仓库为准。客户端写入前带 ETag，冲突就要求用户 refresh 后重提。

## 六、几个必须提前想清楚的问题

1. **私密性**：仓库私有 + 台账加密（`age`/`sops`）二选一。**推荐直接加密**，因为一旦客户端把 token 泄出，代码可以补，历史持仓泄了就是永久的。
2. **数据源稳定性**：akshare 免费但会挂；tushare 免费额度有限。至少配两个源，`scripts/lib/data_fetch.py` 里 try/except 切换。
3. **交易日历**：所有 cron 只在"名义时间"跑，脚本内必须先判断交易日 + 节假日 + 半日市，不然元旦当天也会发提醒。
4. **回测与实盘的时钟对齐**：T7 生成的回测胜率写进 `07_信号台账.expected_returns_*d`；T8 回补 `actual_returns_*d`。**必须用同一份交易日历、同一个 T+1 开盘价口径**，否则对比毫无意义。
5. **推送幂等**：同一 signal_id 30 分钟内不重推。Notifier 里维护 KV 状态。
6. **合规**：这套系统只是个人记账 + 提醒，不涉及代客理财、不涉及自动下单，不需要牌照。但**永远不要把它包装成"给别人用的信号服务"对外发售**，那是另一回事。

## 七、给未来实施 Agent 的落地清单

后续实施时，按这个顺序推进最省事：

1. 先建仓库骨架（scripts/ + skills/ + .github/workflows/），把现有 06_backtest_*.py 挪进去。
2. 写 `lib/data_fetch.py`（先只封 akshare）和 `lib/is_trading_day.py`。
3. 把 T8（台账维护）先做出来，因为它是回测和实盘对比的唯一桥梁。
4. 再做 T1（每日风控），跑通"Actions → 日报 commit → 邮件"最小闭环。
5. 做 Notifier 三通道，切到企微/飞书。
6. 起 PWA 项目，先只做"读"路径（仪表盘 + 台账查阅）。
